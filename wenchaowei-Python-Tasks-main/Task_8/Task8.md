# Task8#

这一期，我们继续用 `FastAPI` 做一个更接近真实业务的小项目。

前面你已经接触过接口、请求参数、`Pydantic` 数据校验这些基础能力，这次的目标不是再写一个“玩具接口”，而是试着完成一个 **结构完整、规则明确、可以直接运行** 的小型后端。

这道题的重点不在于功能做得多复杂，而在于你能不能把：

1. 接口设计清楚
2. 数据校验写规范
3. 基础业务规则处理完整
4. 代码控制在一个简洁、可读的范围内


## 题目##

请使用 `Python + FastAPI` 编写一个 **失物招领 API Lite**。

这个项目的目标是实现一个极简的后端服务，支持：

- 发布一条失物或招领信息
- 查看当前的失物列表
- 按条件筛选记录
- 将某条记录标记为已认领
- 查看当前数据的基础统计信息


## 技术要求##

- 使用 `FastAPI` 作为后端框架
- 使用 `Pydantic` 进行请求数据校验
- 使用 `sqlite3` 作为数据库
- 建议将核心后端代码控制在 `300` 行左右
- 建议使用单文件实现，文件名为 `main.py`

本题不要求：

- 前端页面
- ORM
- 登录鉴权
- JWT
- 文件上传
- 分页

这一题的核心不是“项目做大”，而是“在有限规模内把该做的事情做好”。


## 基础功能##

你必须完成以下 `4` 个接口：

### 1. 发布失物信息

- 路由：`POST /items`
- 功能：发布一条失物或招领信息

请求体建议包含以下字段：

- `title`：物品标题
- `description`：物品描述
- `location`：地点
- `contact`：联系方式
- `status`：状态，取值为 `open` 或 `claimed`

请求示例：

~~~json
{
  "title": "黑色水杯",
  "description": "杯身有贴纸",
  "location": "教学楼A101",
  "contact": "qq:123456",
  "status": "open"
}
~~~


### 2. 查看失物列表

- 路由：`GET /items`
- 功能：返回当前所有记录，并支持按条件筛选

至少支持以下查询参数：

- `status`：按状态筛选
- `keyword`：按关键词筛选，可匹配标题或描述

请求示例：

~~~http
GET /items?status=open&keyword=水杯
~~~


### 3. 修改物品状态

- 路由：`PATCH /items/{id}`
- 功能：根据物品 `id` 修改状态，例如将 `open` 改为 `claimed`

请求示例：

~~~json
{
  "status": "claimed"
}
~~~


### 4. 查看统计信息

- 路由：`GET /stats`
- 功能：返回当前数据的基础统计结果

返回示例：

~~~json
{
  "total": 12,
  "open": 9,
  "claimed": 3
}
~~~


## 数据要求##

数据库表名固定为 `items`，建议至少包含以下字段：

- `id`：主键，自增
- `title`：物品标题
- `description`：物品描述
- `location`：地点
- `contact`：联系方式
- `status`：状态，取值为 `open` 或 `claimed`
- `created_at`：发布时间


## 基础业务规则##

请确保你的项目至少满足以下规则：

1. 新增记录时自动生成 `id`
2. 新增记录时自动写入 `created_at`
3. 查询或修改不存在的 `id` 时，应返回 `404`
4. 非法状态值必须被拦截
5. 所有接口统一返回 `JSON`


## 加分项##

在完成基础功能后，请额外实现下面 `3` 个优化：

### 1. 字段去空白并校验非空

对以下字段进行首尾空格处理，并保证处理后不能为空：

- `title`
- `location`
- `contact`

也就是说，像 `"   "` 这样的输入不能被当作合法值保存进数据库。


### 2. 重复状态更新拦截

如果某条记录已经是 `claimed`，再次将它更新为 `claimed` 时，应返回明确错误提示，而不是直接判定成功。

这个要求是为了体现：你的接口不仅能“改数据”，还要能处理简单的业务规则。


### 3. 增加物品类型字段

请新增 `item_type` 字段，取值为：

- `lost`
- `found`

并让 `GET /items` 支持按类型筛选。

请求示例：

~~~http
GET /items?type=lost
~~~
